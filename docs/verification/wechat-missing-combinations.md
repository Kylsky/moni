# 微信组合场景补查

2026-10-19，接续[上一轮完整场景回归](wechat-scenarios.md)。本轮核对单项功能组合时的遗漏，使用独立合成 D1／DO，不操作桌面微信，不修改个人账本。

## 已复现的问题

1. 同一轮 `prepare_draft` 和 `query_ledger` 均成功时，微信回复直接选择统计，漏掉草稿明细或直接入账收据。人工／直接入账、先记账／先查询共 4 种组合在修复前均失败。
2. 人工确认模式下，一轮允许创建多份草稿，正常回复只读取最后一个工具引用；末次模型失败后的恢复路径也只读取最后一份业务回执。两条输入消费均已保存，但微信只展示最后一份。正常／末次服务失败共 2 项在修复前均失败。

这些用例通过真实本地 WechatBot alarm、会话 DO、D1 和受保护接口复现；模型与微信服务按用例控制。不是只调用排版函数或伪造最终业务结果。相同消息 ID 内容变化的对照用例原本通过。

最小修复在微信回复层汇总本回合全部草稿引用，读取当前 D1 状态并去重；失败恢复也读取全部匹配的业务回执。多份待确认草稿复用原批量核对，缺信息的草稿明确排除；统计与记账结果共同展示。超出完整展示预算时，统计转网页查看，必要时清理确认引用并要求网页核对，不截断后继续开放批准。没有重新执行模型、增加财务权限或改动入账事务。

## 真实模型组合验证

在原有真实微信会话验证脚本增加 `--mixed` 定向入口，复用相同的私密配置检查、网络白名单和临时账本清理逻辑，不重复整条较长流程：

```sh
MONI_REAL_WECHAT_CONVERSATION_SMOKE=1 node scripts/real-wechat-conversation-smoke.mjs --mixed
```

最终构建 `worker-entry-DdNcI4-3.js` 下 5 项业务检查通过：

- 合成午餐 CNY 35 整理为草稿并同轮查询，尚未入账的草稿不计统计。
- 自然语言确认后仅新增一笔正式账目。
- 本人通过受保护接口开启直接入账后，合成公交 CNY 12 同轮返回真实收据与 CNY 47 统计。
- 连续追问按类目分组，保留日期及备注条件，仍为 CNY 47，无额外草稿或账目。

共 4 份回复、9 次主模型和 2 次确认分类请求；11 次真实服务 HTTP 200，未触发摘要。微信传输为可控替身，业务使用真实本地 D1／DO；独立临时存储结束销毁，不能据此宣称腾讯真实收发已重测。
