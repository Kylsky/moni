# S4 多笔草稿与本人确认验收（Issue #15）

2026-10-18。本地真实 D1、每会话真实 SQLite DO、受保护接口；常规模型／报价替身与真实指定模型分别记录。

## 已实现

- 正式会话通过 TanStack AI 的 `get_ledger_context` 与 `prepare_draft` 工具整理收入／支出。只读取当前会话可编辑草稿、账本今天、主币种及现有类目标签，不上传整本正式账目。模型没有正式入账、修改或确认工具，聊天中的“已确认”和工具样式文字不能代替确认命令。
- 每项保留独立名称、日期、原币、金额、类目、标签与选填备注；未写日期／币种采用账本今天／主币。金额缺失或币种歧义保留待补，不猜金额；类目优先复用，无法识别时未分类，标签规范化并去重。
- 外币由应用取适用 ECB 参考报价，保留来源、报价日、方向与主币金额；报价缺失保留待补。本人明确描述的实际主币结算优先，另可在编辑器填写实际值或手填汇率。模型没有填写猜测汇率的工具字段。
- 草稿状态为待补、待确认、已入账、已取消。待补／待确认不参与账目筛选或统计；可编辑、补充与明确取消，错误保留输入。修改后先保存草稿，再核对新结果并确认。
- 模型更新必须引用每项稳定标识，包含当前草稿的全部项目且不重复；允许展示顺序变化，不能按行号串用实际结算或报价。`20` 与 `20.00` 按精确原币金额判等，仅改备注时保留同项既有折算。新增消费另建草稿，不把已有项目静默丢弃。
- 确认核对本人、活动数据集、草稿版本、明确确认与唯一操作标识，在一个 D1 原子批次更新状态并写入所有项目。复用手动记账的 `entryWriteStatements` 金额、固定折算、标签及约束；后项失败时前项和草稿状态一并回滚。旧版本、已取消、已入账、已删除会话和旧数据集均拒绝新入账。
- 模型草稿与报价写入都绑定当前会话执行凭据；在外部请求前检查，提交批次再次核对。删除期间迟到报价不能补写报价、草稿或账目。删除会话会撤销待确认草稿，保留正式账目和备注。
- 单张最多 20 项；模型草稿参数最多 32 KiB，同会话草稿 JSON 总量最多 1 MiB，均明确拒绝而不截断备注。一次回合最多 6 次模型迭代、12 次工具调用，沿用 90 秒期限和上下文／完整消息上限。

## 双端界面

对照 B02 及既有组件规范，沿用黄色本人气泡、透明小票助手、黑描边草稿卡、逐笔编辑、橙色确认按钮与现成图标。PC 展示原币和折合金额，手机保持自然滚动；输入器采用图稿的单行布局，已有会话的手机底部收紧，手动入口继续从新会话及账目页进入。工具执行信息不显示为普通聊天占位气泡，历史与工具结果仍完整保存。

编辑保留逐笔备注、标签、日期和折算依据。语言切换不丢输入，另一设备更新时也保留本机未保存修改；提交继续使用开始编辑时的版本，拒绝覆盖新版本。取消编辑后焦点回到修改按钮。中英、深浅／系统主题和 320px 已检查。
