# 普通会话与微信共用会话行为

2026-10-19。使用者明确要求微信修复同步覆盖普通会话，尤其意图识别。范围限现有记账、草稿确认及查账，不增加正式账目聊天编辑、退款或权限切换。

## 确认的遗漏与修复

此前确认意图分类、批量目标决策只在微信入口执行；网页依赖草稿卡确认按钮。同轮查询后自动入账的统计刷新也只在微信回复组装时处理。新增受保护普通会话回归稳定复现：先查询再自动记午餐 35 元，正式账目写入成功，但工具没有提供更新后的统计。修复前人工模式通过、直接模式失败。

- `conversation-intent.ts` 为两入口提供同一个 TanStack AI 只读分类器：新收支、修改、查询追问、查看待确认、确认全部、否定与歧义沿用同一规则。旧微信导出保留兼容引用，不维护第二套实现。
- `draft-review.ts` 共用目标选择、意图决策和单份／批量确认；继续使用原 D1 财务命令、版本、恢复锁、原子事务和幂等检查。明确全部时仍在事务内拒绝未展示的新完整草稿。
- 网页发送消息时携带草稿卡已渲染的编号及版本快照，模型不能提供该字段。版本变化、取消、异会话、缺信息、提前确认及含修改的同意均不能直接入账；确认文字、真实回执与运行完成状态同时落库。停止识别取消请求，不继续重试。旧 API 不携带展示信息时不增加自然语言写权限。
- 网页还核对上一回合是否实际生成待确认草稿或由程序提出核对；查询、其他话题或暂不确认之后的“好的”即使被分类器误判为同意，也先重新核对。只读取上一回合的有界历史，不因确认而重新加载整段长会话。
- 网页对当前完整卡片建立批量展示范围，明确缺信息草稿不计统计、不会入账；超过 20 笔时保留逐份按钮。微信继续以发送回执、消息创建时间和加密引用证明展示，不把网页请求当成微信消息。
- 同轮查询后自动入账时，共用工具返回重新读取的统计，并保留原查询 ID；网页同回合按 ID 替换结果卡，刷新／重载后仍一致。刷新失败返回显式错误引用，隐藏旧统计卡并保留实际入账结果；模型被要求不得继续引用旧数字。没有改写或删除历史消息。

## 重试混合回复的额外遗漏

原回复同时包含草稿和统计，发送失败后在网页改价或取消，重试仅重建草稿，统计部分消失。改价、取消两个用例修复前均失败。现从已接纳运行的工具历史重新组装本轮两类结果，只做可信查询与排版；纯确认回合继续使用原草稿引用。没有重新执行模型或写账工具。

真实模型脚本只从被忽略、未跟踪且权限受限的本机配置读取服务参数，使用临时合成账本，结束销毁；不向本人腾讯微信发送测试消息、不读取个人账目。记录阶段、请求状态和受限结果，不记录模型正文、私密配置或原始服务异常。
