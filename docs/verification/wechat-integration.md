# 微信入口验证记录

2026-10-19。此记录仅覆盖使用者另行授权的微信扩展，不关闭或改写父规格，也不将真实部署、账号绑定或线上验收提前标为完成。

## 已完成的本地行为

使用 `wechat-ilink-client@0.1.0` 的真实安装包及记录在 pnpm 中的 fetch 注入补丁，经本地真实 Worker、D1 和 SQLite DO 验证以下外部行为。微信、模型和身份公钥服务在常规集成测试中均为可控替身，未使用个人账目。

1. 管理入口仅允许 Access 本人；匿名、其他使用者、跨源写入和伪造绑定参数被拒绝。
2. SDK 通过当前官方要求的 POST 和应用头获取二维码，支持验证码及受限腾讯主机重定向；Token 不进入状态响应，存储中的凭据、二维码状态和消息上下文均为密文。
3. 只接纳扫码确认的本人消息；Bot 回声、群消息、其他发送者和重复投递不执行模型。相邻 uint64 消息 ID 保持精确，正文中的 JSON 文本不会被误改。
4. 接纳记录与游标一同持久化；DO 被驱逐后能继续处理待接纳消息。D1 拒绝初次接纳时保留待处理记录，恢复后仅执行一次。
5. 同一微信会话连续提问保留自身历史；网页可查看来源和历史，其他网页会话保持独立。
6. 草稿、逐笔备注和网页明确确认复用现有业务命令。微信自然语言明确同意与网页按钮复用同一命令，重复确认只形成一笔正式账目。本人明确开启直接入账后，完整草稿可自动入账，权限撤回后不能迟到执行。
7. 查询回复使用数据库计算的结果，区分主币种和原币金额，不采用模型自行生成的统计数字。
8. HTTP 200 中的业务错误仍算失败。回复失败重用同一 client_id，最多三次重试且不重跑 AI；确认丢失时也不重新创建业务操作。
9. 断开立即撤销渠道执行约束、终止活跃回合、更新业务修订号；迟到模型结果不能写草稿或发回复。删除的会话不复活，本人可明确新建微信会话。
10. 恢复暂停阻止渠道执行；业务恢复保留来源、历史和备注，排除凭据、绑定授权和发送任务；旧绑定不能跨数据集执行。旧 v1 备份缺少 source 时按 web 兼容。
11. Token 失效要求重连；不可解密的二维码状态也可重新绑定；未配置或上游故障不影响原网页功能。

## 本次真实本机联调

本人已扫码绑定真实微信。通过安装 SDK、构建 Worker、本地真实 D1/DO 接收两轮本人消息；真实模型共 4 次请求均 HTTP 200，完成两轮持久化会话并生成一份带独立备注的可编辑草稿，正式账目仍为 0。没有代替本人确认该草稿。更新权限功能后，本机重启仍保留绑定、历史与草稿，默认权限为 review。

真实模型配置从被忽略、未跟踪、权限 0600 的本机私密文件读取；QR 图及加密连接状态仅在被忽略的私密目录。未把个人消息、微信身份、二维码、Token 或服务配置附入本记录。私密值扫描仍通过。

此联调仅监听本机回环地址，使用隔离账本和本地签名的测试身份，拒绝外部 Host 与跨源请求。它验证实际微信和模型组合，**不验证生产 Cloudflare Access 或云端持续运行**。初始联调进程的发送统计没有把无 ret 字段的成功响应计入，因此不以该计数宣称端侧展示验收完成；新进程按 HTTP 与业务返回码共同记录。

## 自然语言确认追加验证

已取消确认码和固定命令。通过真实配置的同一模型验证 19 组**合成**语义输入，全部符合“是否明确同意入账”的预期：确认、记上吧、就这样入账、没问题记下来、当前核对问题下的“好的”和英文明确同意均可识别；否定、修改要求、疑问、条件、引用、感谢、强迫输出意图、部分批准及跨多草稿批准不产生确认。

上述真实语义测试只调用模型，没有写账、没有发送微信消息，不能代替本人端侧入账验收。本地真实 D1/DO 的 35 项微信集成另验证原子入账、重复同意、驱逐恢复、未展示前的提前确认、上下文切换、并发修改、断开后的迟到结果及模型异常。模型只返回意图；草稿目标、版本、幂等及渠道权限由程序检查。

随后真实微信收到第三轮本人消息，生成第二份独立草稿；该进程真实模型 4 次请求均 HTTP 200，发送接口成功回执 1 次。现有两份草稿仍未由代理代为确认，正式账目为 0。更新后的自然语言确认需本人继续在微信实际操作后再记录结果。

## Markdown 排版追加验证

核对腾讯官方当前插件的变更日志、发送路径及 Markdown 过滤测试后，草稿改为加粗状态、独立标题及金额、分行字段与加粗合计，多笔逐项编号。实现与版本依据见[排版核查](../research/2026-10-19-wechat-message-format.md)。

本地真实 D1/DO 配合受控模型、微信和汇率替身的微信集成共 40 项通过，新增覆盖：中文单笔完整消息、外币参考汇率与实际结算两种多笔消息、标题／标签／多行备注的 Markdown 转义及原文保留、转义后超长回复不允许确认未展示的完整草稿。原有自然语言确认与幂等检查继续通过。格式、类型及 503 个中英文键检查通过。

默认构建和私密值扫描通过。已使用新构建重启本机隔离联调服务，受保护状态仍为 connected、review，原有两份草稿与 0 笔正式账目保留，页面返回 200；没有重新扫码或创建云端资源。

没有通过模型重新排版或计算金额，没有代替本人确认既有草稿。本次没有把构造的输出消息当作微信手机客户端已实际渲染的证据；实机视觉效果仍待本人收到新版消息后核对。

随后按本人明确要求，将指定的既有草稿使用当前排版补发到本人微信。真实发送接口成功回执已验证；补发前后只读核对草稿及正式账目数据完全一致，目标仍为 ready，正式账目仍为 0。没有重新调用模型、生成新草稿或执行入账。此结果确认服务端接收，不代表本人手机显示已验收。临时操作工具及加密上下文已清理，仅在被忽略的本机目录保留脱敏结果。
