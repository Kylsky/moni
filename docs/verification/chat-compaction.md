# 同会话自动摘要、滑动窗口与完整历史

2026-10-19，使用者明确授权接入官方能力，微信持续使用同一会话，完整历史保留，并处理原来的整会话存储门槛。本页替代早期 S0／S4／S5 中 40 条上下文、1,000 条／1 MiB 历史及累计草稿 1 MiB 的阈值；其他财务、权限、输入和备份规则保持各自约束。

本页记录接入时的验证结果；后续扩大场景后的真实模型、故障回归及修复见[微信完整场景回归](wechat-scenarios.md)。

## 实现

- 使用已发布 `@tanstack/ai-compaction 0.2.0` 的 `withCompaction`、`summarizeOldest` 和 `evictOldest`，未使用官网尚未发布的后台摘要等接口。只投影 `providerMessages`，`withPersistence` 继续保存完整权威 `messages`。
- 每次模型调用重新计算保守预算：16,000 估算 token、通常约 8,000 近期 token、2,500 摘要预留。近期窗口按完整用户回合切分，当前输入与所有工具调用／结果必须完整保留，不能单纯按数组条数截断。保守估算不等于供应商精确计数。
- 摘要按有界输入批次滚动生成，独立于财务工具，使用私密模型配置；总时间有界，空结果、过长结果、网络或模型失败均回退。回退不覆盖旧历史或有效检查点，也不产生伪成功摘要。官方 metadata 检查点按数据集／会话隔离、来源 hash 校验、版本化策略标识复用，DO 重启不要求重新开会话。策略标识不含私密模型或服务配置。
- 待确认草稿及 ID／版本从 `get_ledger_context` 读取，查询条件从完整原始查询记录读取；金额重新查询正式账目。摘要不能批准、撤回或修改账目。原微信创建时间／展示时间、身份、版本、原子入账和幂等检查继续生效。
- 新输入可靠接纳改为单行追加。SDK 的 `saveThread` 保持完整替换语义，通过逐行比较、分块 upsert 和尾部删除在同一 D1 事务实现，只写变化，不把整段历史塞入一个 SQL 参数。历史按 200 行读取，网页默认约 50 条并补全回合边界，按钮可加载更早消息；游标绑定数据集和会话。
- 移除整会话 1,000 条／1 MiB，以及同会话累计草稿 1 MiB 固定门槛；单份草稿保留请求大小约束，单条历史保留 256 KiB。备份与恢复同步允许超过旧整会话门槛，仍保留整体 10 MiB／100,000 行验证。摘要检查点是可重建缓存，不进入业务备份；删除会话清理其摘要。

## 验证入口

- `pnpm check`：受保护接口、真实本地 D1／DO、可控模型与微信，包含超过 40／1,000 条继续记账、超过 1 MiB 历史读写、只更新变化行、分块事务失败回滚、来源绑定游标、工具完整配对、DO 重启复用、摘要失败／空／超长安全回退、批量和单份确认幂等、超过旧窗口后继承查询条件并刷新金额、长历史完整备份恢复、删除摘要。
- `pnpm exec playwright test tests/e2e/chat.spec.ts`：生产构建下桌面和手机的历史分页、键盘操作、无重复消息、不重放模型请求，以及原有发送／刷新／停止／重试流程。
- `MONI_REAL_CONTEXT_SMOKE=1 node scripts/real-context-smoke.mjs`：只读被忽略、未跟踪、0600 的私密服务配置；创建独立临时 D1／DO，用合成项目代号和长对话验证真实摘要、摘要中指代回答、重启复用、原始历史保留、分页及请求去重，不创建账目或草稿。输出只含结果、阶段、次数与状态；不输出配置、提示词、摘要或原始错误。临时数据库结束即删除。
- `MONI_REAL_WECHAT_CONVERSATION_SMOKE=1 node scripts/real-wechat-conversation-smoke.mjs`：真实模型和意图识别，微信网络收发使用可控替身；通过构建 Worker 的受保护接口建立合成绑定，由真实本地 WechatBot alarm、会话 DO、D1 跑完整处理流程。覆盖连续两笔记账、逐笔备注、未入账提醒、核对不入账、自然批量确认、相同消息重投、再次确认及继承条件查账。使用独立临时账本，结束销毁，不操作桌面微信或修改个人数据。
- `pnpm build`、`pnpm check:private`：构建与私密值扫描。

## 本轮结果与边界

最终 `pnpm check` 通过格式、520 个中英文键、23 项单元测试、268 项 Worker 测试和 TypeScript；保留 1 项原有跳过项。`pnpm build`、`pnpm check:private` 通过。生产构建下桌面与手机的 10 项会话浏览器用例全部通过。

全量 Worker 测试使用默认并发时，本机多项用例超过测试的 5 秒门槛，并出现后续状态连锁失败；将 Miniflare 测试进程并发限制为 3 后全量通过，没有增加产品或测试的超时时间。

真实模型首次探测触发回退，未将此轮记为通过；最终构建独立复测完成 2 次真实摘要和 2 次正常问答，4 次 HTTP 200，确认合成代号能从摘要中回答、重启后复用、同一会话不变、80 条原始历史完整保留、无账目／草稿写入、重复请求不重放。

微信处理流程的真实模型自动联调通过：12 次正常模型请求、6 次意图识别，18 次 HTTP 200，8 份测试回复。两条连续输入分别生成 11 元与 22 元草稿；查账前未入账，提醒明确不计统计；完整核对后自然回复“都没问题，全部确认入账。”只新增 2 笔；相同消息重投不再调用模型或发送回复，再次确认不增账；随后两次查询均从 D1 得到 33 元，按类目追问保留原备注筛选。整个流程沿用同一合成微信会话。此项微信传输为替身，不冒充腾讯端到端收发。

分页初次浏览器用例的精确文本定位遗漏角色前缀，实际数据已显示。进一步核对还发现 SDK 在 UI 再切页时可能用首条可见消息 ID 替换适配器游标；补齐受数据集／会话约束的 ID 解析及旧无 ID 消息的稳定页面 ID，桌面和手机逐页加载全部 120 条均通过，没有跳页或重复。API 另覆盖 104 条逐页回读、非法页参数，以及跨会话游标拒绝。

新增权限验证覆盖：摘要请求进行中删除会话，并模拟 DO 取消通知失败。D1 撤权后，后续摘要批次、检查点与主模型调用均不能继续；旧历史不会被迟到结果复活。每个摘要批次及回到主模型前都重新检查执行权。

本地已恢复原微信绑定和原会话，实际腾讯轮询继续工作；核对个人账目 6 笔逐项未变、待确认草稿 0 份。旧确认、失败的旧描述不会自动重放。本轮没有新发真实微信消息；不将项目内测试输入标为腾讯来源。

使用者明确选择日常回归直接在项目内测试微信会话流程，使用真实私密模型配置与独立测试账本，无需反复人工在手机操作。网页正式微信会话仍为历史／草稿核对入口，不为测试放开其他来源的确认权限。微信客户端显示、腾讯身份及消息时间戳传输、网络异常和云部署运行是独立验收层，适配器或 SDK 改动时仍需对应验证。

SDK 当前仍要求完整权威消息数组，并为检查点校验来源前缀；D1 读写已分页／分块，界面已分页，但模型回合仍需组装完整历史，处理成本随历史增长。已移除人为整会话门槛，不承诺无限物理容量；规模接近 Worker 内存或账号数据库容量前，需要进一步的归档适配器。不能通过静默删历史规避平台限制。
