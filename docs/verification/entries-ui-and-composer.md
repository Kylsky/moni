## 账目页范围

沿用统计页的奶油色背景、橙色主操作、细边框与卡片层级，整理账目筛选、手机卡片、PC 表格、详情、手动记账／编辑及关联退款表单。输入框复用 Base UI Input，币种与类目使用现有 Select，收支切换使用现有 SegmentedControl；没有新增依赖。日期沿用 Input 的 `type="date"`，弹出的日期选择器由浏览器提供。

保留逐笔备注、原币／固定折算展示、筛选与导出、回收站、退款限额、校验及失败重试。再次点击当前收支类型不会清空已选类目。未修改账目计算、AI 或微信业务逻辑。

## 输入框已确认原因与最小修复

普通窗口和长历史下未复现截断。缩放可以稳定复现：布局视口高度 700 px，1.25 倍缩放后的 VisualViewport 高度 560 px，但原输入表单底部仍为 700 px。只把贴底偏移调整为两者差值 140 px 后，表单底部变为 560 px，表单父容器与文本框高度均未变化。因此本次确认的是可见区域缩小后贴底位置未同步，尚不能据此判断用户当时的具体浏览器设置。

在共享 ChatSession 中监听 VisualViewport 的 resize／scroll 和窗口 resize，把实际不可见的底部间距写入表单 CSS 变量。手机保留既有底部导航间距，取导航间距与可见区域间距的较大值；卸载时清理监听。无需修改外层高度或聊天数据。

回归测试先在旧构建上观察到缩放断言失败，再在修复后通过，覆盖 1.25／1.5 倍缩放及恢复；另覆盖新／旧会话、50 条历史、8 条近期会话、短 PC 窗口和 320 px 手机窄屏。
