# S5 保存现账与原子恢复（Issue #19）

2026-10-18。前置 #18 已完成。所有验证使用独立合成账目和受保护应用接口，实际本地 D1／会话 DO；不调用真实模型或报价服务。

## 恢复边界

- 只有完整封存、摘要匹配且未过期的准备可取得五分钟恢复锁。锁内暂停账目、草稿、会话和消息写入，撤销原会话运行权并将运行中回复标记中断。取消通知失败仍由数据库写入条件保证隔离。
- 本人须实际下载锁内一致的当前 JSON 备份，再勾选保存确认，打开第二次确认。下载摘要和版本由服务端记录，确认请求必须同时匹配准备、会话、活动源账本、锁、摘要及版本；客户端不能自行提交普通写入的锁权限。
- 恢复在同一个 D1 原子批次中归档未完成回复、取消导入待确认草稿、移除目标执行权，最后切换活动指针。D1 最终更新失败或被忽略时，前述所有修改整批回滚。确认命令幂等，响应丢失后沿用同命令重试，不再次覆盖恢复后的新记录。
- 完成后整页重新加载，丢弃旧编辑器、响应、流和确认卡。所有写入均核对活动数据集；旧 DO、alarm、持久化适配器和正式命令不能污染新账。导入会话保持完整消息，未完成回复显示归档中断，不自动再次调用模型。
- 取消、锁超时、刷新和开始响应丢失都有恢复入口。新锁不能被迟到旧取消清除；超时后重新开始必须重新下载并保存最新现账。取消只清理非活动准备，现账可继续记账。
- 源账本保留三分钟供运行中请求退出，之后本人读取触发逐个安全清理；失败整批回滚并在后续读取重试。清理条件始终排除活动数据集，不影响已恢复数据。
- 备注、原币金额、固定折算、退款关联、回收站及会话在完整备份往返保持。未导入密钥、登录身份、部署配置、旧请求收据或运行许可；恢复后继续使用当前部署的私密环境。
