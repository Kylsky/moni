# S3 外币退款与折算尾差验收（Issue #11）

2026-10-18。本地真实 D1、受保护应用接口及独立合成账目；不请求新行情或模型。

## 行为与金额口径

- 默认沿用原消费币种及确认比例，保留原来源和报价日期。USD 100 按 7.20 记账后退 USD 30，默认折合 CNY 216；确认前展示原币、采用依据、主币金额和剩余 USD 70。
- 新增默认折算分配额，独立于实际到账金额保存。部分退款以精确比例计算并在主币最小单位舍入，受剩余默认折算额约束；退至全额时使用剩余折算额，保证默认合计精确冲回原确认金额。界面说明使用了剩余确认折算额。
- 明确实际主币到账额时优先实际值，同时保留该笔默认分配额。因此后续默认退款不会吞掉实际结算差额。例如先退 USD 30 实收 CNY 210.33，再默认退 USD 70 得 CNY 504，累计 CNY 714.33，净支出保留 CNY 5.67；不新增汇兑损益分类。
- 正原币退款折算后可以为零，适配原币及主币的 0/2/3 位精度和金额上界。金额中间计算使用 BigInt，有效比例及历史折算不依赖后续行情。
- 金额和覆盖方式/实际金额相同的退款，修改备注或日期保留原主币金额、默认分配及快照；添加/清除实际覆盖必须重新核对。原消费改价不暗改既有退款，新的退款根据剩余确认折算额预览。
- 删除会释放原币及默认折算分配。恢复保留原已确认快照并重新检查余额：原币不能超额，默认分配不能超出原主币金额，恢复为全额时分配须能精确冲回。新旧退款混合后不能满足这些规则的旧记录，恢复明确失败；不偷偷修改其历史金额。
- 原消费改低于既有默认分配，或在原币已退全额时改成不一致的主币金额，同样原子拒绝，需先处理关联退款。

## 数据库与并发

0009 迁移保留旧记录并补齐主币退款的默认分配。数据库视图集中汇总当前有效原币和默认分配，触发器保护新增、编辑、恢复及原消费改价；关联关系不可改指另一条账。

确认命令在同一 D1 原子批次中校验活动数据集、原消费/退款版本、已退原币额及分配额，防止把先前预览的尾差在竞争后悄悄换成另一个金额。同操作收据重读仍在重新计算之前；失败不留下半笔退款。
