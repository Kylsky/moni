# 微信统计排版验证

2026-10-19。仅更新微信文字统计展示，图片能力另做主来源核查，不将协议可行性当作已接通图片。

## 本轮实现

- 加粗突出净支出或收入；支出、退款、匹配笔数分别列出，保留日期、时区、主币种和查询时间。
- 根据已验证查询结果的 view，分别展示汇总、类目、标签和时间趋势。标签保留重叠提示；退款保留发生日口径，不重算数据库金额。
- 外币原币汇总与主币种固定折算金额分开，收入查询不混入无关支出指标。空结果不显示成实际消费为零。
- 自由输入的筛选条件和分组名称按字面转义。长度预算按完整条目选择，保留摘要及口径；省略时明确标记。长趋势优先保留最近有记录的时段，并按时间顺序呈现。条件本身过长时提示网页核对，不静默删除筛选条件。
- 不新增模型调用、依赖、云资源或固定网页链接。草稿沿用同一 Markdown 转义函数，原确认及幂等逻辑保持原流程。

## 本机联调边界

已构建新版本并重启本机隔离服务。受保护状态接口确认微信已连接、入账模式为本人确认；中文页面及其引用的 5 个脚本／样式资源均返回 200。未主动发送个人统计、改变草稿或账目，未提交、推送或部署云端。

更新前进程实际出现一次 `context_limit`，只读核对旧会话已有 43 条模型消息（包括工具记录），超过既定 40 条上下文限制。此限制独立于排版功能；按总规格第 23 条及技术方案 8.5，保留旧历史并提示新建会话，不自动清空或换会话。本轮没有扩大上限或加入自动摘要。当前旧会话不能据此宣称修复后的真实连续统计已通过；手机端新格式仍待本人在可用会话里核对。
