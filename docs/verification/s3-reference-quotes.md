# S3 历史参考汇率验收（Issue #9）

2026-10-18。受保护应用接口、本地真实 D1 与独立合成账目；与真实公共服务结果分开记录。

## 已实现的本地行为

- 固定请求 Frankfurter v2 的 ECB provider，按发生日取得 EUR 原生报价；只发送币种和日期，不发送账目名称、备注、金额、登录信息或模型配置。没有报价服务 Key。
- 核验方向、完整币对、同一实际报价日、正报价、有限小数和响应上限。报价日不能晚于发生日；未来发生日或超过上游 14 天适用窗口的报价转为待补。
- 原生两腿以 BigInt 有理数计算交叉比例，金额仅在最后按主币最小单位舍入。显示汇率最多 12 位小数并使用约等号；显示近似值不反向覆盖保存的精确比例。
- 服务器在活动数据集中保存不可由客户端伪造的报价凭据。保存账目核对凭据所属数据集、币对、发生日及本人确认的主币金额；手填报价不能冒充 ECB 来源。相同取价操作可重读同一证据。
- 确认后保存原币、主币、精确比例、来源和实际报价日。行情变化或仅改备注、类目、标签不重估历史；金融字段变化后展示新折算并要求确认。
- 手机与 PC 提供参考、手填、实际结算三种依据。发生日和实际报价日分别展示；失败保留输入，允许重试和改用手填/实际金额。实际结算明确提供时优先。

## 运行时兼容问题与回归

症状：受控接口测试成功，编译后真实 Worker 内取价在发出网络请求前返回不可用。

确认原因：当前 workerd 不支持 Fetch 的 `redirect: 'error'`，会直接抛出 TypeError；最小 workerd 复现已确认该错误。改为 `redirect: 'manual'`，对 3xx 与所有非成功状态拒绝，不跟随外部地址。

回归入口：`tests/e2e/rates.spec.ts` 通过编译后的真实 Worker/D1 发出受控 ECB 请求；`tests/worker/rates.test.ts` 核对请求不跟随重定向并拒绝 302。该兼容结论针对当前锁定的 Wrangler/Miniflare/workerd 版本，升级后沿用行为回归。

## 真实服务边界

准确接口、报价精度和非报价日合同见 [官方调研记录](../research/frankfurter-ecb-contract.md)。09:12 UTC 的 12 项 curl 公共请求返回 HTTP 403 / Cloudflare 1010；这是此前观察，未更换身份规避拒绝，原因尚未确定。

随后使用正常 Node 应用客户端及本机已有代理，运行 `scripts/real-fx-smoke.mjs`，经编译后受保护 Worker 与真实临时 D1 验证成功；加强原币、方向、备注及表数量断言后复验仍通过。4 次实际公共请求均为 200：

- USD/CNY 工作日 2024-05-15：ECB 来源、EUR 原生两腿方向及实际报价日通过；合成 USD 20 明确确认后保存精确比例和最终主币金额。
- 周日 2024-05-19：实际报价日为 2024-05-17；元旦 2024-01-01：实际报价日为 2023-12-29。
- BHD/CNY 2024-05-15：上游 200 但缺少完整币对，应用返回 424；没有保存不完整凭据。
- 未登录请求为 401 且没有外部调用；修改备注不重新取价，回读原币 USD 20、更新备注及固定折算不变。最终仅 1 条正式合成账目和 3 条完整报价凭据。

复验需显式设置 `MONI_REAL_FX_SMOKE=1`；采用已有代理时由本机环境设置 `NODE_USE_ENV_PROXY=1`。脚本不读取私密配置，只向固定报价地址发送币种及日期，日志不含凭据、私人输入或个人代理设置；结束即销毁临时库。默认执行跳过真实请求。
