## 本次确认的问题与修复

分类模型应只返回一次 `classify_draft_confirmation`。原来的 `calls` 计数位于已通过参数校验的服务器工具回调内。模型返回一条合法确认和一条枚举错误、额外字段或损坏 JSON 的分类时，SDK 会将参数错误作为工具结果处理；合法回调只执行一次，旧计数仍为 1，程序因此接受了部分响应。

排查区分了三个可能原因：只计算成功回调、SDK 丢掉第二次调用、流解析合并调用。已安装 SDK 的事件处理与红绿回归证明：调用起始事件仍然存在，错误发生在以成功回调数代替整包调用数。没有修改 SDK。

最小修复在共享 `src/lib/conversation-intent.ts`：同时检查 TanStack AI 提供的 `TOOL_CALL_START` 次数和通过校验的执行次数，两者都必须恰好一次。发现第二个调用直接按无效响应返回，不能授予确认，也不因畸形响应自动重试。原有 15 秒＋一次 30 秒的暂时故障重试、超时、取消、权限及版本校验保持原样。

这项计数仅作用于只读分类器，不限制主会话模型正常的多工具记账和多组查询。没有新增模型请求、依赖或配置。正常一条调用的 JSON 参数被拆成多个流片段时，仍可正确确认。

两个入口的受保护接口回归先验证畸形混合响应不入账，再验证下一条合法确认只入账一次。所有交易都在临时合成 D1／DO 中，个人账本未参与。
