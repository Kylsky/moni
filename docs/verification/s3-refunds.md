# S3 关联主币退款验收（Issue #10）

2026-10-18。本人受保护接口、本地真实 D1 与独立合成账目；无真实财务资料或模型请求。

## 已实现

- 退款为关联原支出的独立正式账目，保留自身发生日与可编辑备注，不当作收入。可部分/全额登记、修改，并从原消费打开退款详情或返回原消费；原币金额及主币预览经本人确认。
- 查询按退款自己的日期计入退款和净支出。9 月消费 200、10 月退款 50，9 月仍列支出 200，10 月退款 50、净支出 −50。名称/备注检索不串用原消费备注。
- 退款的类目与标签动态继承原消费，原消费改类目/标签或合并标签后筛选同步；任意标签匹配不重复计数。标签关联数量包含其继承的退款及回收站记录。
- D1 外键和触发器保护同数据集、有效支出、币种、累计有效原币退款限额；每条命令还核对活动数据集、原消费版本、退款版本和操作收据。失败整批回滚，不留孤立退款或半笔写入。
- 有效退款存在时，原消费不能删除、变为收入、改币种或改低于已退金额。退款软删后不统计；恢复重新检查原消费状态、币种和可退余额。原消费彻底删除前需处理仍关联的回收站退款，避免不可恢复引用。
- 同操作同内容重试返回原结果；换内容或过期版本拒绝。退款编辑省略发生日时保留原值，修改/清空备注不变更日期。无法保存或刷新时保留表单输入并提供核对余额的入口。
- 双端采用批准的 B07-r2 风格：PC 原币字段与右侧主币预览，手机自然滚动、并排取消/确认。保留中英文、主题、键盘焦点、明确标签和错误提示。删除确认及回收站标明退款类型。

## 确认并修复的主题缺陷

症状：设置选择“跟随系统”，直接进入普通账页后改变系统主题，页面仍停留在原主题。

根因：媒体查询监听原来由设置页的 ThemeSwitcher 持有，离开设置页会卸载。已把主题应用函数提取为 `src/lib/theme.ts`，由根布局统一持有监听，设置控件继续使用同一函数。

回归入口：`tests/e2e/refunds.spec.ts` 在未访问设置页时切换系统深浅色，检查主题和正在编辑的备注；既有 `home.spec.ts` 保留手动深色/系统主题的设置与导航回归。结论针对本仓库当前主题生命周期，后续布局调整时保留这些行为检查。
