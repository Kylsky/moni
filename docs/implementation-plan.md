# Moni v0.1 分阶段实现计划

日期：2026-10-18。依据：[需求基线](../PRODUCT.md)、[技术方案](technical-design.md)、[平台核查](research/2026-10-18-platform-feasibility.md)与[官方 skill 复核](research/2026-10-18-tanstack-official-skills.md)。

架构已确定为 D1 + DO：D1 保存账本、草稿、完整会话与运行记录，每个会话一个 DO 协调并执行 AI 回合。先验证两者协同、关键适配和数据原子性，再完成手动记账与确定性统计，然后接入 AI、会话和备份恢复，最后验证一键部署。每阶段都应交付可检查的行为；全部完成并通过 19 项需求验收后，才满足 v0.1。

官方 skills 下载与资料核查已完成；以下实现阶段尚未执行，不授权业务编码、应用依赖安装、付费调用或部署。下文的测试、迁移和联调均指获得相应实施授权后的工作，不在本轮执行。各阶段按退出条件推进，不以估计天数替代完成证据。

## 2 S0 关键技术验证

### 工作内容

- 以已下载的官方 skills 和复核笔记为起点，在授权后安装与锁定兼容的 TanStack AI 包组，核对 peer dependencies，转用所选版本的包内 skills 与源码；不从过时的 skill 版本标注推定依赖版本。
- 验证同一 Worker 中 TanStack Start 请求入口与会话 DO 类导出、binding、SQLite 类迁移及类型生成的组合；用受控模型验证 Worker → DO → SSE 客户端的响应和取消传播。
- 验证以环境、可信 owner、`dataset_id` 和会话 ID 路由 DO；同会话多设备进入同一对象，不同会话独立。DO 不提供绕过 Worker 鉴权的公开入口。
- 用受控模型响应验证新增用户输入、文本、工具调用、工具结果和草稿引用的保存与恢复；确认可靠保存输入后才调用模型，前端伪造历史不能覆盖服务端记录。
- 验证在 Worker/DO 环境内注入可信范围的 D1 `messages`、`runs` 适配器，通过所选版本的官方 conformance 检查；声明未采用的 stores 与可选方法，不复制过时的 store 键枚举。DO 协调与并发另测。
- 验证 DO 的短状态转换、忙碌拒绝、回合期限、alarm 幂等及重启核对；模拟本地预留与 D1 接纳之间、模型调用前后、终态保存失败时的中断，保证未可靠保存输入不调用模型，普通重发不另发模型请求。
- 验证 D1 快照、草稿和正常收尾核对回合凭据、期限和活动数据集；超时后的条件终止只处理匹配旧回合，不补写内容或误伤新回合。不再实施 D1 分布式抢占/续租或通用 LockStore，不将 DO 单线程或 `withLocks` 当成自动整轮互斥。
- 验证流消费和必要持久化完成后才释放回合；刷新时对真实活动回合显示忙碌，失去执行实例的回合先失效再允许明确重试，不自动 join、重播或后台继续。
- 验证模型上下文选择与完整历史保存的边界；任何裁剪都不能经 `saveThread` 覆盖掉保留历史。核实 DeepSeek 模型的工具、结构化输出及组合能力。
- 在 D1 对应测试环境验证原子 batch、退款约束、零行更新、唯一操作标识和冲突返回。
- 验证非活动数据集分批装载、最终指针切换、过期恢复锁与旧请求拒绝路径；旧 DO、alarm 和输出流不能越过恢复锁或写进新数据集。
- 核实 ECB 历史报价与非报价日行为、币种清单和消息/备份大小的技术上限；确定金额精度与上传限额。

### 交付与退出条件

形成最小可运行验证与结果记录，确定 DO 内部入口与流转发、D1 Adapter 契约、回合状态转换、跨存储故障核对、数据库约束和恢复步骤。必须覆盖双设备并发、DO 重启、重复 alarm、迟到写入及终态持久化失败；两套存储不能被假定为同一个事务。失败的假设先修订技术方案，不带入正式实现。

模型工具可先使用受控替身；这一步的模拟成功不能写成 DeepSeek 真实调用成功。真实服务调用与资源操作遵循后续明确授权范围。

## 3 S1 私有骨架与初始化

### 工作内容

- 同步 `AGENTS.md`、项目身份和 README 中的模板定位，保留凭据、生成文件及 `workers.dev` 约束。
- 建立覆盖 SSR、server functions、聊天和导出的身份检查，绑定唯一 owner；缺配置时默认拒绝。
- 增加 D1 迁移、基础表和活动数据集机制，所有持久化 Interface 带可信数据集范围。
- 在同一 Worker 导出会话 DO 类，加入 namespace/class binding、SQLite 类迁移和最小协调状态初始化；建立受鉴权路由使用的内部调用入口，先用受控执行验证，不接真实模型。
- 分离本地、预览和生产的 D1 与 DO namespace；预览使用虚构数据，不能连接真实私人账本或生产会话协调状态。
- 建立聊天、账目、统计、设置、回收站的最小导航，复用现有 UI 和主题。
- 建立经鉴权的主币种与时区初始化，语言优先级与中英文页面结构；将私有页面设为 noindex。
- 增加空白配置示例、`.dev.vars*` 忽略规则，并再生成 Worker 类型。

### 验证与退出条件

本人可进入初始化，缺少 Access 配置、无效或错误 audience/issuer/签名、过期令牌、非本人均不能读取或写入账本。直接请求服务端函数和流接口不能绕过检查。

本地测试身份替身不能由生产请求选择。模板中的应用路径必须 404 等旧断言按实际需求替换，中英文与键盘导航仍成立。

D1 SQL 迁移与 DO 类迁移均可从空环境初始化；DO 内部调用不能被客户端指定对象地址或伪造 owner 绕过。基础手动记账路径直接访问 D1，不依赖 DO 可用或 AI 已配置。

## 4 S2 手动记账与纠错

### 工作内容

- 实现金额与日期基础规则、命令校验、草稿准备和用户确认；缺金额不能保存，缺日期默认账本今天。
- 实现收入、支出、默认类目、自定义类目、标签与标签合并；保留稳定标识。
- 为每笔账目及草稿项保留独立可选备注，支持填写、修改、清空及关键词检索；仅改备注不重新换算。
- 实现账目列表、筛选、分页、编辑、回收站、恢复与彻底删除确认。
- 确认和修改经过同一账目 Module，使用唯一操作标识和版本检查；创建首笔正式账目后锁定主币种。
- 为多币种保留完整数据模型，手动输入换算依据可用，不等待 AI 接入才能记账。

### 验证与退出条件

AI 完全未配置时，用户仍能完成手动记账与纠错。连点、网络重试和同一草稿在另一设备确认仅入账一次；不同真实消费可分别保存。

金额校验、时区与月末区间、分类标签、备注编辑检索、删除恢复、版本冲突通过针对性测试；刷新后正式记录及备注仍存在。

## 5 S3 多币种退款与统计

### 工作内容

- 接入明确 ECB 来源的历史报价，保留实际报价日期，提供手填与实际结算覆盖；失败保留待补草稿。
- 实现整数金额、精确比例换算、入账快照和影响换算的编辑确认。
- 实现关联退款、部分退款、原币累计限额、发生日统计、默认原比例退款和尾差处理。
- 实现 UI、导出和 AI 将共用的筛选与聚合 Interface，按主币种返回收入、支出、退款、净支出和分组趋势。
- 实现月度收支、类目占比、趋势与可点开的匹配明细。

### 验证与退出条件

需求中的 CNY 35 加 USD 20、原汇率退款、跨月退款、历史金额固定与原币查询结果均正确。

必须覆盖并发退款、超额退款、软删除后恢复、原消费改金额/币种、标签关联导致重复统计、舍入尾差和无匹配记录。模拟报价通过后，再单独记录真实汇率服务验证结果。

## 6 S4 AI 记账查账与会话

### 工作内容

- 使用 TanStack AI、React hook、官方 SSE 工具与 `openaiCompatible` 接入 DeepSeek，显式配置模型能力，地址与模型由部署配置提供，Key 由 Secrets 提供。
- 由会话 DO 执行 TanStack AI，完成内部流转发及活动回合状态；D1 会话工厂保存完整消息 parts、工具结果与 `runs`，支持新建、切换、删除与恢复会话，DO 不复制完整历史。
- 工具只允许准备草稿、获取汇率和查询账本；正式入账走独立的用户确认命令。
- 让自然语言转换为结构化记账或查询意图；相对日期、金额与统计交给确定性规则处理。
- 逐笔保留本人明确提供的备注细节；“午餐在肯德基吃的 35”保留“在肯德基吃的”，多笔草稿不串用备注，查账可按“肯德基”关键词筛选。
- 支持连续追问、歧义澄清与受限上下文，使用当前账本重查；查询卡片由程序渲染金额、日期与筛选条件。
- 落实 S0 验证过的 DO 预留 → D1 可靠接纳 → 模型执行 → 持久化收尾协议，处理同会话忙碌、重启、断网、超时和明确重试；保存失败不返回可误解的成功状态，不重放入账。
- 删除会话时先在 D1 撤销可写状态，再通知 DO 清理；无法及时通知时，旧回合及 alarm 仍不能复活消息或影响已入账账目。

### 验证与退出条件

先用受控模型响应覆盖所有工具路径，再以经授权的真实 DeepSeek 小样本验证工具调用和结构化输出。

一句话多笔草稿、备注细节保留与关键词查账、缺失金额、模糊类目、美元换算、三个月外卖查询、上个月追问、切换会话、刷新及第二客户端恢复均成立。伪造历史、工具结果、草稿版本或会话 ID 不能越权或触发写入。

同会话的两设备同时提交时，只有一个新回合被接纳，另一设备得到忙碌状态且不调用模型；不同会话独立处理。DO 重启、重复 alarm、过期凭据和终态保存失败均有明确结果，同一请求重发不悄悄再调用模型。

连接中断时已入账数据保持一致，重新打开会话可区分运行中、已完成和已中断。DO 本地状态与 D1 不一致时先核对，不自动重调模型；上下文处理不丢失可查看的历史。断线续流、WebSocket 和自动后台继续均不作为本阶段交付。

## 7 S5 导出备份与恢复

### 工作内容

- 建立 CSV 列定义与公式注入防护，以及带格式版本的完整 JSON 备份契约。
- 一致性导出覆盖 D1 中的有效和回收站账目、逐笔备注、标签、关联、换算依据、设置、会话及恢复所需业务状态，排除 Secrets、部署身份和 DO 协调状态。
- 实现校验、预览、分批暂存、现账备份、最终确认、数据集切换及失败取消路径。
- 恢复锁阻止新回合和旧 DO 写入；切换后按新 `dataset_id` 使用新 DO，旧执行凭据和确认动作失效，未完成运行按适用的 `failed`/`aborted` 归档并显示中断说明。
- 验证清理旧 DO 协调状态、alarm、暂存与旧数据集的有界重试；清理通知失败不影响当前账本的写入防护。

### 验证与退出条件

对一个含中英文备注、空备注、CNY/USD、部分退款、已删除记录、标签合并和多会话的数据集进行导出恢复，逐项比对备注、业务结果与统计；CSV 同样保留备注并正确处理文本转义。

畸形文件、未知版本、无效关联、超额退款、超过文件限制、中途失败、锁超时、切换版本冲突和旧请求写入均不能破坏当前账本。恢复时仍在运行的旧 DO、延迟 alarm 和输出流不得污染新集；无需原 DO 状态即可从 JSON 恢复完整业务数据。JSON 中不包含 API Key；恢复不覆盖当前 owner 或 Access 配置。

## 8 S6 部署与发布验收

### 工作内容

- 配置官方部署按钮、D1 和 DO bindings、D1 SQL 迁移及 DO 类迁移，用全新部署实例验证 Worker 入口、DO 类导出与初始化流程。
- 写清 Zero Trust、Access 本人策略、API Key、模型、币种与时区的设置步骤及故障排查。
- 完成移动端、桌面、中英文、焦点、表单错误、聊天卡片和图表文字替代；同步 README、DESIGN、模板文案与相关测试。
- 执行与最终变更相关的格式、翻译、类型、单测、D1/DO 集成与端到端检查，再构建部署产物。
- 在获得部署授权后，验证正式入口、预览入口、直接业务接口、非本人、导出和会话均受保护；核对 D1 与 DO namespace 均隔离，并验证部署更新中活动回合的中断处理。

### 验证与退出条件

下表 19 项需求全部有结果。分别报告模拟、本地集成、真实服务、部署与线上验证状态；未执行的步骤明确保留为未验证。

构建通过、资源创建成功或 Access 显示登录页，都不能单独证明完整记账、真实 AI、导出恢复和非本人隔离已成立。

## 10 交付顺序与停止条件

S0 的验证先于大规模页面开发。S1 建立 D1/DO 部署基础；S2 和 S3 先形成不依赖模型与 DO 会话执行的可用记账内核，S4 在 DO 中复用它。S5 以 D1 数据集边界保障恢复，不以清空数据库或仅通知 DO 停止替代安全恢复。

每阶段若发现需要增加新云服务、改变权限、改变换算或退款口径，先回到技术方案和需求基线处理，不能借实现细节悄悄扩大范围。

当前最先可执行的工作是 S0，但本轮只交付方案与计划。编码、依赖安装、真实服务调用和部署均尚未开始。

## 11 微信可选入口（排期待定）

[微信入口与专用会话设计](wechat-entry-design.md)已确认共用账本、独立微信会话及网页查看历史的关系；具体发布版本未确定，不加入上表 19 项 v0.1 必验条件，也不启动实施。

后续排期时，以 S4 已有会话与工具能力为复用基础，按以下顺序落细：

1. 确定本人绑定、微信会话重置/删除和入账确认交互，保留同一套账本规则。
2. 验证账号级消息接收与会话 DO 的衔接、可靠接纳、防重复、重启恢复及运行费用，再确定接收层实现。
