# Moni v0.1 双端 UI 审查稿

这套稿延续已选定的第一张风格，覆盖首版主要页面和关键状态，共 20 张审查画板。16 张首版流程、1 张微信扩展草案、1 张深色英文代表页均提供 PC 与手机对照；另外 2 张状态画板提供双端组件对照。

**当前状态：使用者已于 2026-10-18 确认 UI 并授权素材提取，8 份字标与助手透明 PNG 已交付；业务编码和部署尚未开始。** 需求与技术方案仍以 [PRODUCT.md](../../../PRODUCT.md) 和现有技术文档为准，设计稿不扩大功能范围。

## 打开与反馈

打开 [审查画册](review.html)，通过目录、上一张和下一张浏览，点击画板可打开完整原图。推荐先审查 B02、B03、B05 至 B08，再看设置、数据和异常状态。

后续反馈可以直接引用编号，例如“B05 手机列表太挤”“B07 退款说明需要更突出”。当前画板版本已获使用者确认，素材提取授权已生效；文件见 [素材清单](assets/README.md)。功能和分类图标按使用者要求复用现成的 Tabler Icons。

画册只展示当前审查版本；旧版保留在 archive/，不作为实现依据。文件对应关系见 [review-manifest.json](review-manifest.json)。

## 视觉与布局

- 暖纸色背景、浅色内容面、黑色描边、橙色主要按钮、黄色对话气泡，延续小票助手与橙色铅笔。
- PC 采用侧边导航和宽内容区；对话页可显示最近会话，其他页面使用自己的内容。手机采用对话、账目、统计、设置四个底部入口；初始化和受限页不显示私人导航。
- 草稿、查询结果和表单按任务分组；列表优先使用行分隔，避免每行都套独立卡片。手机表单与长报告允许自然滚动。
- 页面中重要金额优先，原币金额、折合金额、报价日期和来源需要同时可查；退款与收入使用文字明确区分。
- 主要按钮突出当前任务。普通删除先进入回收站，永久删除显示再次确认；弹窗采用 PC 居中、手机底部展开的共用容器。

目标逻辑视口为 PC 1440 × 1024、手机 390 × 844。生成图是审查位图，实际像素和画板上标注的逻辑视口并不完全相同，不可将其直接拉伸为网页或直接裁切为生产素材。

## 同一套组件应覆盖的交互

以下是静态稿之外的状态说明，复用已有表单、提示和弹窗样式。它们尚未实现，不能用位图代替功能验收。

| 组件 | 必须覆盖的行为 |
| --- | --- |
| B02 草稿确认 | 支持逐项编辑，包含各笔独立备注；未确认不计统计。确认中禁用重复提交；成功后显示“已入账”及账目明细入口。失败保留草稿，不显示已保存。 |
| B06 记账表单 | 新增与修改共用布局。收入使用独立收入类目，标签可多选，备注选填且可补充、修改或清空。修改原币金额、币种、日期或换算依据时，展示新的折算结果供本人重新确认；仅改类目、标签或备注不重新取汇率。 |
| B05 手机筛选 | 筛选按钮展开底部面板，包含日期、类型、类目、标签、关键词和原币；关键词包含备注。支持应用及清空，返回列表显示当前条件。无结果复用 B17 的中性空状态。 |
| B07 退款 | 显示原消费与可退原币余额；超额退款就地报错。默认沿用原消费汇率，实际主币种到账金额为选填。部分退款处理尾差，原消费改小金额不得低于已退款金额。 |
| 账目详情操作 | B06 复用为编辑表单；普通删除复用 B18 的确认容器，文案为“移入回收站后不计统计，可恢复”。有关联退款的原消费先提示处理退款。 |
| B09 类目与标签 | 添加及改名使用简短表单；支出和收入类目不混用。合并前选定保留标签并展示影响，不根据 AI 建议自动合并。 |
| B10 回收站 | 恢复成功后重新计入报表；操作失败保留原状态。永久删除确认中显示具体账目，不提供清空全部入口。 |
| B11 基础设置 | 主币种锁定时不可修改。语言提供跟随浏览器、简体中文和 English；主题提供浅色、深色、跟随系统。时区修改不改历史记账日期。AI 页面只提供状态及配置说明。 |
| B12 与 B18 恢复 | 文件无效时停在预览阶段；先保存当前账本备份，再允许整本替换。替换中禁用重复操作；失败不留下部分替换的账本。 |
| B14 访问验证 | 根据实际原因显示配置未完成或无访问权限，不泄露私有数据或凭据。配置说明入口不提供匿名指定所有者的能力。 |
| B03 自然语言查询 | 条件含糊时在原会话先澄清。连续追问保留查询上下文，但重新查询当前账本。明确查询 USD 时同时展示 USD 原币合计和 CNY 折合金额；按类目、标签或趋势分组仍使用同一结果容器和明细入口。 |
| B17 会话状态 | 未配置 AI、处理中禁用发送；失败后可重试。不得把“无匹配记录”解释为实际没有消费；不能凭旧回答认定当前统计。 |

## 账目备注补充

2026-10-18 使用者补充确认：每笔收入、支出和退款均支持独立的可选备注。沿用现有 PC 与手机稿中的编辑、表单和详情位置，备注补充不修改 UI 图；随后已确认 UI 并完成授权范围内的素材提取。

例如输入“午餐在肯德基吃的 35”，整理为名称“午餐”、金额 CNY 35、类目“饮食”、标签“午餐”、备注“在肯德基吃的”。AI 保留本人明确提供的商家、地点与用途等细节，不编造信息，多笔草稿分别保存各自备注。只输入“午餐 35”时，备注可为空，不阻断入账。

B02 通过原有编辑入口核对备注，B06 支持填写、补充、修改和清空，B05 列表沿用次要描述位置展示摘要，详情展示完整备注。B05 的关键词搜索及 B03 的自然语言查账包含备注，例如按“肯德基”查找或汇总消费；修改备注后使用更新内容匹配。

备注随正式账目保存，删除会话不删除备注；退款可填写自己的备注。仅改备注不重新取汇率或改动金额。B20 的 CSV 导出和 JSON 备份、B12 的恢复流程均完整保留备注。

## 自查修正与实现细节

已修正的项目包括账目列表筛选与汇总、手动入口独立性、退款金额和币种、统计图退款方向、设置导航、语言来源、时区文案，以及忙碌状态的发送按钮。具体版本记录见 review-manifest.json。旧版中发现的问题不作为最终规则保留。

实现时沿用已确认的手机信息密度、主次按钮和小票助手使用位置。字形、描边、圆角和图标在生成图间仍有细微差异，开发时统一为可复用组件；字标和助手使用已交付素材，功能及分类图标使用现成库。

浅色目标色值为背景 #fff8e8、内容面 #fffdf7、正文 #171313、次要文字 #62594d、橙色 #ff6038、黄色 #ffd84a。深色代表为背景 #181414、内容面 #242020、正文 #fff8e8。色值是实现起点，不表示全部位图已通过对比度检测。#ff6038 上白字的计算对比度约 3.01:1，只适合足够大的粗体文字；小按钮应使用深色文字或更深底色。实现时逐组件核对 WCAG AA、焦点与禁用态，不用缩小文字解决拥挤。

B19 仅展示深色英文的代表页，其他页面不重复铺满所有语言与主题组合。微信绑定、扫码、微信内确认方式与网页续聊方式仍待定；B16 的只读历史是一份交互提案，沿用 [微信入口设计](../../wechat-entry-design.md) 的待定边界，不表示微信排期已进入 v0.1。
